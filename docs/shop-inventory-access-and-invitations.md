# Inventory access and staff invitation follow-up

Apply `supabase/shop-inventory-permissions-20261017.sql` in Test after the inventory foundation. It is transactional and rerunnable. It retains the hardened technician role preset and the existing AP defaults, and does not change saved AP overrides. Inventory has independent `inventory.read`, `inventory.receive`, and `inventory.manage` keys. Owners retain access; admins default to all three; writers default to read/receive; other roles default to none. This office inventory workspace remains limited to owner/admin/writer, and catalog/corrections remain owner/admin even if a writer is granted manage. Receive/manage require View inventory. The user editor exposes the new controls. Reapplying older permission migrations can replace these definitions; apply this follow-up last.

For QA, turn off both AP boxes for the Shop C writer, leave View inventory and Receive inventory checked, and save. Confirm catalog/history and a confirmed receipt work without AP access. Disable Receive inventory: reads work, receiving is denied. Disable View inventory: direct inventory access is denied. Re-enable both for subsequent QA. Owner/admin catalog changes still work; technician direct access remains denied. The temporary AP grants used during foundation QA should be removed manually if no longer intended.

Staff invitations now expose a same-host sign-in link carrying the invitation token in returnTo. Login accepts that validated local invitation route before requiring membership. Already-confirmed/existing accounts can sign in without another signup. The invitation watches authentication state so email-confirmation sessions reveal Accept invitation. A wrong account is identified and can sign out and return to the preserved invitation through login. Invalid/expired invitations remain denied by the existing RPC; no membership is created by the client or by login alone. Email delivery and Supabase redirect allowlists are unchanged.
